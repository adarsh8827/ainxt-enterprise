# LLD — AgentStudio integration (Ecosystem → AgentStudio direction)

**Purpose**: the opposite direction from `LLD/legacy-bridge.md` (which surfaces AgentStudio's own content *into* the Ecosystem catalog, read-only). This file covers the reverse: making Ecosystem-installed capabilities usable *from inside* AgentStudio's own UI and runtime. A 15th LLD file, added in M5 when tasks B-23/B-24 needed a home — none of D-0's original 13 areas fit (matching the precedent `desktop-local-cache.md` set as a 14th, added later for a new area).

## Files / functions

- **Task B-23 — "missing dependency" surfacing (resolver)**: `AgentStudio/backend/app/engine/native_engine.py`'s `NativeEngine._resolve_catalog_tools()` gains one new optional parameter, `missing_dependencies: Optional[list] = None`. The method's own two existing tool-drop sites (a catalog lookup that raised, or one that returned nothing) each gain one additive line: `if ECOSYSTEM_AGENTSTUDIO_MISSING_DEP and missing_dependencies is not None: missing_dependencies.append(tool_name)`. The flag itself is read defensively — `from core.config import ECOSYSTEM_AGENTSTUDIO_MISSING_DEP` wrapped in `try/except ImportError` (falls back to `False`) — since `AgentStudio/backend/app/core/config.py` is a *separate* config module from the main repo's `core/config.py`, and AgentStudio's standalone dev-mode service (`:8002`, not used by any compose service, per `AgentStudio/backend/Dockerfile`'s own comment) has no path back to the main repo's module at all.
- **Task B-23 — UI wiring**: of `_resolve_catalog_tools()`'s 7 call sites, `NativeEngine._run_agent()`'s resolution of a node's own picker-attached tools (`data.get("tools") or []`, the node's `data.tools` array saved by `CatalogPicker.jsx`) is the one wired up — it's the only call site resolving tools the *user* attached (the other 6 resolve always-present platform singletons: `code_executor`, `read_skill_file`), so it's the only one where "dropped" can mean "an Ecosystem-sourced skill/tool this graph references was uninstalled or force-disabled since the graph was saved," a fact worth surfacing. A per-call local, `node_missing_deps: list = []`, is declared before the `resolved_tools_cache` cache-hit branch (REQ-P3-2 — a loop's cache-hit re-entries skip re-resolving, so they report nothing new rather than raising or carrying over a stale list) and passed as the out-param. The SSE events already emitted at this point in the method — `agent_start` (terminal agent) and `agent_progress` (intermediate agents) — additively spread a `missing_dependencies` field into their payload **only when the list is non-empty** (`{"missing_dependencies": node_missing_deps} if node_missing_deps else {}`), so a run with nothing missing produces byte-identical SSE to before this task existed. `AgentStudio/frontend/src/features/workflows/editor/ChatPanel.jsx`'s SSE handler (4 call sites — the live-stream and buffered-replay parsers each have an `agent_start` and an `agent_progress` branch) reads `data.data?.missing_dependencies` into a new `missingDependencies` field on the execution-log entry it appends; `buildAgentTimeline()` (now additively exported, for testability) carries that field onto the matching agent's timeline row (refreshed per loop round, same rationale as the existing `condition` snapshot). The thinking-timeline JSX renders each missing name as a small amber "unavailable" chip, styled distinctly from (but visually consistent with) the existing tool chips (`.thinking-tool-chip--missing`, `workflow-editor-premium.css`) — mirroring the visual convention `CatalogPicker.jsx`'s `.catalog-picker__ecosystem-badge` (task B-24) already established for Ecosystem-related metadata in this app. Resume runs (`resume=True`, the HITL "before_tool" reviewer-override path) don't re-emit `agent_start`/`agent_progress` at all — unrelated to this task — so this signal is scoped to the initial run of a node, not every resume.
- **Task B-24 — skill picker merges Ecosystem skills**: `AgentStudio/frontend/src/components/common/CatalogPicker.jsx` gains one additive `useEffect`, active only when `kind === "skills"` and the flag is on: calls `platformFetch('/ecosystem/capabilities?surface=agent_studio')` (an existing helper in `AgentStudio/frontend/src/config/api.js`, already used for other main-repo platform endpoints — never a new fetch helper) and merges any results not already present (by `name`) into the SAME `catalog` state array the native `GET /skills-catalog` fetch already populates, each tagged `_ecosystemSourced: true`. That tag drives a small `Marketplace` badge next to the entry's name, both in the attached-chip strip and the add-menu list (`.catalog-picker__ecosystem-badge`, `AgentStudio/frontend/src/index.css`). `GET /skills-catalog` and its response shape are completely untouched — the merge is a second, independent fetch, never a change to the first.
  - **Flag mechanism**: a build-time env var, `VITE_ECOSYSTEM_AGENTSTUDIO_SKILLS`, read via `isEcosystemAgentStudioSkillsEnabled()` — a function, not a module-level `const`, specifically so `vi.stubEnv()` can mock it per-test (a module-level `const` only reads `import.meta.env` once, at first import, which silently defeated an early draft of this task's own tests — see Edge cases). Not a live backend flag lookup: this keeps "flag off → zero extra network calls" trivially true and cheap to verify, rather than requiring the picker to first ask the backend whether to ask the backend.
  - **Not yet built, disclosed**: runtime *execution* of a picked Ecosystem-sourced skill still needs to go through `skill_view`/`read_skill_file` (task B-15) rather than AgentStudio's own `skill_files`/`skills_catalog` tables, per this task's own original instruction ("Runtime loading of an Ecosystem-sourced skill's content, once picked, goes through skill_view/read_skill_file — never a read of skills_catalog/skill_files"). That is a `native_engine.py`-side dispatch change (detecting that an attached skill's name is an Ecosystem namespace, not a native catalog entry, and routing its tool-call execution accordingly) — the same file, and the same risk profile, task B-23 already flagged as too deep/unfamiliar to safely modify further in this pass (it could not even be imported standalone for testing here). This task's own test suite instead proves the one thing it's actually confident is true and safe: **zero writes ever reach `skills_catalog`/`skill_files`** from the picker itself, regardless of which list a picked skill came from — the picker only ever calls `onChange()` with a plain in-memory object, never persists anything on its own (persistence is the parent `ConfigPanel`'s job, mirroring the attached array onto `node.data.{tools|skills}`, per this component's own pre-existing docstring — unrelated to and untouched by this task).

## API and DB changes

None. `_resolve_catalog_tools()`'s own DB reads (`workflow_repo.get_tool()`, AgentStudio's `tools_catalog`) are completely unchanged — this task never writes anywhere, and never touches the Ecosystem catalog's own tables either (that's task B-24's job, via a read-only `GET /ecosystem/capabilities` call, not a DB read from AgentStudio's backend directly).

## Sequence diagrams

```
NativeEngine._resolve_catalog_tools(requested, ..., missing_dependencies=None)
  → for each requested tool name:
      lookup in tools_catalog (async, concurrent via asyncio.gather)
      → found: wrap as _CatalogTool, append to the returned tools list (unchanged)
      → not found / lookup raised:
          log a warning (unchanged, always happens)
          IF ECOSYSTEM_AGENTSTUDIO_MISSING_DEP and a caller passed a list:
            append tool_name to that list  <- the only new behavior
  → return tools  (the SAME list shape as before this task -- never changed)

NativeEngine._run_agent(node_id, node, ...)          [the wired call site]
  → node_missing_deps = []
  → catalog_tools = await self._resolve_catalog_tools(
        data.get("tools") or [], ..., missing_dependencies=node_missing_deps)
  → (unrelated work: KB retrieval, sample-doc wiring, prompt build, ...)
  → yield make_sse("agent_start" | "agent_progress", {
        "agent": name, "node_id": node_id, ...,
        **({"missing_dependencies": node_missing_deps} if node_missing_deps else {}),
    })

ChatPanel.jsx SSE handler (×4: {live-stream, buffered-replay} × {agent_start, agent_progress})
  → addExecutionLog({ type: 'agent_start', agent, nodeId,
        missingDependencies: data.data?.missing_dependencies || null })
  → buildAgentTimeline(): step.missingDependencies = log.missingDependencies || []
  → JSX: one amber "<name> unavailable" chip per entry, next to the existing tool chips
```

## Edge cases and errors

- **A module-level `const` reading `import.meta.env` silently defeats `vi.stubEnv()`-based test mocking — a real bug caught while writing this task's own test suite, not by review.** An early draft of `CatalogPicker.jsx` read the flag as `const ECOSYSTEM_AGENTSTUDIO_SKILLS = import.meta.env.VITE_ECOSYSTEM_AGENTSTUDIO_SKILLS === 'true';` at module scope — evaluated exactly once, at first import. Vitest's `vi.stubEnv()` patches the live `import.meta.env` object correctly, but that patch happens *after* the module (and its already-evaluated `const`) was first imported, so the component never saw the stubbed value; only the "flag off" test (which happened to match the unstubbed default) passed, while every "flag on" test silently exercised flag-off behavior instead of failing loudly. Fixed by reading the flag inside a function (`isEcosystemAgentStudioSkillsEnabled()`), called fresh on every effect run, at the negligible cost of one extra property read per render.
- **`NativeEngine` is a shared singleton across concurrent requests** (its own docstring cites `self._singleton_tool_cache` — "Singleton tool cache for platform utilities that never change at runtime"). This ruled out the obvious-looking design of recording missing dependencies as instance state (`self.missing_dependencies = [...]`) — that would leak one request's missing-dependency list into a completely unrelated concurrent request's response. The out-parameter design (`missing_dependencies: Optional[list] = None`, populated per-call, never stored on `self`) avoids this entirely — enforced by `test_missing_dependencies_is_never_stored_on_self`, a real regression test for exactly this failure mode, not just a design note.
- **Seven existing call sites, only one signature change, zero behavior change for six of them.** `_resolve_catalog_tools()` has 7 call sites across `native_engine.py`, each in a different execution context (top-level agent run, sub-agent construction, workflow node re-entry, etc.). None of them pass `missing_dependencies` — the parameter's default (`None`) means every one of the drop-site checks (`missing_dependencies is not None`) is false regardless of the flag, so this task changed the *signature* (additive-only, a new optional kwarg) without changing *behavior* at any of the 7 sites.
- **UI wiring closed a previously-disclosed gap.** An earlier pass of this task shipped only the resolver-side out-parameter, deliberately not wiring it to any UI surface — identifying the one safe call site among 7, in an unfamiliar ~8,000-line file that couldn't even be imported standalone for testing here, was judged too risky to rush. That identification has since been done with static reading only (no import, no execution): `_run_agent()`'s picker-attached-tools resolution is the only one of the 7 resolving user-attached (as opposed to always-present platform-singleton) tools, and it already sits inside a method that streams SSE events the frontend consumes — see the "UI wiring" bullet above and the sequence diagram. `AgentStudio/backend/tests/test_missing_dependency_signal.py` was extended (not replaced) with source-string tests pinning down that exactly one call site passes the out-param, that the local is declared before the cache-hit branch, and that the SSE payload change is additive-only.
- **Resume runs don't get this signal.** The HITL "before_tool" reviewer-override path (`resume=True`) attaches ad-hoc tools via its own, separate `_resolve_catalog_tools()` call (one of the other 6 call sites) and never re-emits `agent_start`/`agent_progress`. A tool that goes missing only on a resume iteration — as opposed to the node's initial run — won't produce a chip. Disclosed, not fixed: resume's tool-attach path exists for a narrow, already-risky reviewer-override feature, and widening its scope was judged out of bounds for this task.

## Flags

`ECOSYSTEM_AGENTSTUDIO_MISSING_DEP` (`core/config.py`, default off) — task B-23, a backend Python flag, read defensively (see above). `ECOSYSTEM_AGENTSTUDIO_SKILLS` — task B-24, a **frontend build-time** flag (`VITE_ECOSYSTEM_AGENTSTUDIO_SKILLS`, `AgentStudio/frontend`), independent of and not synchronized with any backend flag of the same conceptual purpose — a real, disclosed seam (see How to extend).

## Tests

- `AgentStudio/backend/tests/test_missing_dependency_signal.py` (9 tests, task B-23 — 5 from the resolver-only pass, 4 added for the UI-wiring pass) — source-string style, matching the existing convention `test_sample_doc.py`'s own native-engine plumbing checks already established in this file (importing `native_engine.py` directly pulls in the main repo's `core.*` stack; confirmed directly — a standalone import attempt from this environment hung rather than completing, even with both the repo root and `AgentStudio/backend` on `PYTHONPATH`). Covers: the flag is read defensively with a fail-closed fallback; the new parameter is optional with a `None` default; both drop sites record when the flag is on and a list was supplied; the original warning logs are untouched; the missing-dependency state is never stored on `self`; exactly one call site (the picker-attached-tools resolution) passes the out-param; `node_missing_deps` is declared before the cache-hit branch; the SSE payload change is additive-only (both `agent_start` and `agent_progress`). Run for real (not just `py_compile`) in a throwaway container built from the `ainxt-enterprise:local` image with the live repo bind-mounted over `/app` — all 9 pass; `python -m py_compile` on the whole file also re-confirmed after the edit.
- `AgentStudio/frontend/src/components/common/__tests__/CatalogPicker.test.jsx` (5 tests, task B-24 — **the first real component test in this frontend package**; `AgentStudio/frontend`'s `vitest.config.js`/`vitest.setup.js` were already configured for this, but no test file had ever been written against that config before this task). Covers: flag off is provably zero ecosystem network calls (not just an empty merge); flag on merges and badges both lists; `kind="tools"` never triggers the merge (skills-only); picking an ecosystem-sourced skill calls `onChange()` with it, with zero `POST` calls; the ecosystem endpoint failing degrades silently, native picker unaffected. `AgentStudio/frontend`'s own build (`npm run build`) re-verified after this change: succeeds.
- `AgentStudio/frontend/src/features/workflows/editor/__tests__/buildAgentTimeline.test.js` (3 tests, task B-23's UI-wiring pass — **the first test file for `ChatPanel.jsx`**, which previously had none; `buildAgentTimeline` is exported additively, purely to make this possible, without touching the file's sole pre-existing `export default ChatPanel`). Covers: a log entry with no `missingDependencies` produces an empty array on the step (not `undefined`/`null`, so the JSX's `.length > 0` guard is safe); a log entry with names produces a step carrying them; a loop's second round with an empty list correctly clears a first round's non-empty list (no stale carry-over) via the same collapse-into-one-row path `loopRound`/`condition` already use. Run for real via `npx vitest run` (both this file alone and the package's full 2-file/8-test suite) — all pass.

## How to extend

B-23's resume-run gap (see Edge cases) is the most direct next step: `_run_agent`'s `before_tool` HITL override path resolves reviewer-added tools via its own `_resolve_catalog_tools()` call and never re-emits `agent_start`/`agent_progress`, so a dependency that goes missing only on a resume iteration is invisible today. Wiring B-24's runtime-execution half (routing a picked Ecosystem-sourced skill's actual invocation through `skill_view`/`read_skill_file` instead of `skills_catalog`/`skill_files`) needs the same care as B-23 did: identify where `_CatalogTool`'s dispatch decides *how* to fetch a tool/skill's content, and branch on `_ecosystemSourced` (or an equivalent server-side marker persisted alongside the attached skill) before assuming AgentStudio's own tables. Unifying the two independent flags (`ECOSYSTEM_AGENTSTUDIO_SKILLS` frontend build-time vs. a hypothetical backend equivalent) into one source of truth is a real, disclosed gap worth closing before this feature ships broadly — today, a deployment could build the frontend with the flag on while having no backend-side equivalent concept at all (harmless today, since the backend `GET /ecosystem/capabilities` endpoint is unconditionally available regardless of any AgentStudio-specific flag — but worth tightening before this feature is considered fully specified).
