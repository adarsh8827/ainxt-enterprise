# LLD — External sources catalog crawler (`services/ecosystem/catalog_crawler/`)

**Purpose**: builds the pointer-file catalog that will live on the `ecosystem-index` orphan branch (docs/ecosystem/EXTERNAL_SOURCES_PLAN.md). This LLD covers what's landed so far on `feature/ecosystem-external-sources`: the crawler itself, its three source adapters, signing, and the pointer/report schemas. **Not yet landed** (tracked in the plan doc, not here): the instance-side sync worker (§5), install-from-catalog (§6), the admin Sources screen (§8), live search (§10), and the actual `ecosystem-index` branch + its GitHub Actions workflow — those come after sources.yaml clears stop point 1.

## Files / functions

- `services/ecosystem/catalog_crawler/pointer_schema.py` — `PointerEntry` (dataclass: namespace, item_type, display_name, description, category, tags, source_kind/url/ref/path, license_spdx/evidence, compatibility, content_hash, attribution, crawled_at, remote_only). `pointer_file_path()` returns `catalog/<item_type>/<publisher>/<name>.yaml`. `to_yaml_dict()`/`from_yaml_dict()` round-trip the on-disk YAML shape. `build_index_shards(entries)` groups entries by `item_type`, sorted by namespace, into the `index/<item_type>.json` shape.
- `services/ecosystem/catalog_crawler/sources_config.py` — parses `docs/ecosystem/catalog/sources.yaml` (the reviewed crawl allowlist) into `GithubRepoSource`/`GithubTopicSearchSource`/`WellKnownSource`/`McpRegistrySource`. `load_yanked(path)` reads `yanked.yaml`'s flat namespace list (missing file == nothing yanked). Read-only — this module never writes either file; changes go through a normal reviewed PR (plan §7).
- `services/ecosystem/catalog_crawler/crawl.py` — `run_crawl(sources_path, yanked_path, output_dir)`: for each enabled source, calls the matching adapter's discovery function, keeps only license-allowed candidates, runs `services/ecosystem/gate/static_safety_stage.py`'s `run_fast_path()` over the actually-fetched content as a crawl-time pre-filter (the full 7-stage gate still runs, unconditionally, at install time — this only screens out an obviously-bad candidate before it's ever written to the catalog), computes `content_hash` over the manifest text + bundled files, then writes one pointer YAML per surviving entry plus the sharded `index/*.json`. Filters out anything in `yanked.yaml` before writing. Returns a `CrawlReport`.
- `services/ecosystem/catalog_crawler/crawl_report.py` — `CrawlReport` (included/excluded lists), `excluded_by_reason()` (bucketed Counter), `to_markdown()`/`to_dict()` — the stop-point-2 artifact.
- `services/ecosystem/catalog_crawler/signing.py` — `sign_index_bytes(data)` / `verify_index_bytes(data, bundle_bytes, trusted_identity, *, allow_online_trust_root_refresh=False, trust_root_path=None)`, keyless Sigstore signing via the crawl workflow's own GitHub Actions OIDC identity (package: `sigstore==4.5.0`, Apache-2.0; imported lazily so this module loads fine without the package installed). `TrustedIdentity(issuer, subject)` is what a verifier checks the signer against — a fork must configure its own (plan §2); there is no default that trusts every possible signer. Outside a CI job with an ambient OIDC credential, `sign_index_bytes()` raises `RuntimeError` by design (verified directly, not mocked, in `tests/services/ecosystem/catalog_crawler/test_signing.py`). **Verification is offline by default**: `TrustedRoot.from_file()` loads the pinned, checked-in `vendor/sigstore_trusted_root.json` (Sigstore's public production trust root, fetched once via a real TUF refresh, 2026-09-28) instead of fetching one over the network — confirmed directly against `sigstore-python` 4.5.0's own source that the resulting `verify_artifact()` call makes zero network requests (its `RekorClient` is constructed but never invoked given a bundle with an embedded inclusion proof, which every bundle `sign_index_bytes()` produces has). `allow_online_trust_root_refresh=True` is the one opt-in exception, contacting `tuf-repo-cdn.sigstore.dev`.

## Adapter additions (additive, existing adapters untouched)

- `services/ecosystem/import_adapters/github_repo.py`'s new `search_repos_by_topic(topic, page=1)` — GitHub topic search, discovery-only: surfaces *candidate* repos for a human to add to `sources.yaml` via a reviewed PR. Never called by `crawl.py` itself (no source in `sources.yaml` currently enables it) — a discovery aid for maintainers, not part of the automated crawl path yet.
- `services/ecosystem/import_adapters/well_known.py`'s new `discover_skills_at_well_known(domain)` — lists every entry at a domain's modern-or-legacy index (mirrors `discover_skills_in_repo()`'s shape: one candidate dict per entry, license evidence + allow/deny verdict, nothing raised for a single entry's own failure). Includes the fetched `skill_md_text`/`files` on allowed candidates so the crawler can hash/fast-safety-check without a second fetch.
- `services/ecosystem/import_adapters/mcp_registry.py` (new file) — `list_servers(cursor=None)` / `discover_mcp_servers(max_pages=20)` against the official MCP Registry (`https://registry.modelcontextprotocol.io`, API v0.1). License comes from the entry's own npm/PyPI package metadata (fetched fresh from `registry.npmjs.org`/`pypi.org`'s JSON APIs), or an OCI package's explicit `licenses` annotation — never from the registry entry's own free-text fields. A server with no installable package (`packages: []`) is returned `remote_only=True, allowed=False` — catalog inclusion for those needs a human ToS review (plan §4), never automatic.

## Reuse (per the plan's §12 reuse map — nothing here is a second implementation)

`crawl.py` calls `github_repo.discover_skills_in_repo()`/`import_from_github_path()`/`import_from_github()` and `well_known.discover_skills_at_well_known()` exactly as they already exist for the manual admin-import path (`LLD/external-import.md`) — the license-inheritance chain, SSRF guard, and fetch cache are all shared, not reimplemented. `services/ecosystem/compatibility.py`'s `classify_compatibility()` and `services/ecosystem/license_policy.py`'s `is_allowed_license()` are likewise the same functions the rest of the ecosystem service layer already uses.
